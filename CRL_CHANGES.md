# Dual-CRL-PPO: изменения относительно `purejaxgcrl`

Основа — `dual_leo_ppo.py` репозитория MichaelTMatthews/purejaxgcrl, commit `eafccd995ac2736df5fbc05ac4bb6b5d58cfcce7`. Папки `envs/`, `models/`, `logz/` и файл `wrappers.py` повторяют нейминг исходного проекта. Перенесены только модули, импортируемые тренировочным сценарием. Лицензия исходного проекта лежит в `LICENSE`.

## Что изменено в коде

1. **`models/crl_models_gc.py`**. Взяты две сети `LEONetworkConvSymbolicCraftax` и `LEONetworkFlat` из `models/pqn_models_gc.py`. Сверточные и полносвязные блоки оставлены. Выход `num_goals × action_dim` со sigmoid заменён на признаки каждого действия размерности 64 и обучаемые признаки целей. Их скалярное произведение даёт `f(s,a,g)` из раздела 2 статьи. Для PPO сеть считает действия только заданной цели, для обучения критика — все цели только выбранного действия. Это сокращает промежуточные массивы при больших наборах целей. Блоки помечены комментариями `CRL change`.
2. **`crl_targets.py`**. Новый модуль реализует формулы (4), (6), (7), (8). Масса состояния делится поровну между всеми достигнутыми целями. Вместо одного случайного будущего состояния используется сумма доступных будущих состояний с весами `(1−γ)γ^(k−1)` до `k_max`, нормированная по доступным смещениям. Отсутствующая масса присваивается поглощающему классу `∅`. При заданном `--crl_termination_discount` масса целей дополнительно умножается на `1−γ_term^Δt` до наблюдённого завершения эпизода. В коде комментариями отмечены построение меток, усреднение и поглощающий класс.
3. **`dual_crl_ppo.py`, инициализация и rollout**. Учитель LEO заменён на CRL сеть. PPO, GAE, сбор действий и схема минибатчей сохранены. Сохраняются оценки действий только текущей цели вместо полного массива «цели × действия». Предикаты `goal_achieved` из исходного проекта по-прежнему определяют семантические цели. Наблюдения после автоматического сброса среды исключаются из целей достигнутых в терминальном переходе, поскольку исходные обёртки возвращают уже сброшенное наблюдение. Удалены неиспользуемые `next_obs` и `reward_all_goals` из перехода. Комментарии стоят непосредственно перед изменёнными блоками.
4. **`dual_crl_ppo.py`, обновление учителя**. TD цель LEO и bootstrap заменены на soft categorical cross entropy по всем целям и поглощающему классу с фиксированным логитом 0. Используется действие, выполненное в траектории. Цели перемешиваются тем же образом, что и соответствующие переходы. Это соответствует формулам (3) и (7). PPO bootstrap сохранён для GAE.
5. **`dual_crl_ppo.py`, обучение PPO**. Сохранена имитация лучшего действия учителя. Теперь `argmax` берётся по `f(s,a,g)` для заданной цели, согласно формуле (9). Value BC удалён, потому что логит CRL не является оценкой Q. Коэффициент policy BC по умолчанию линейно затухает до нуля. Опциональный режим softmax оставлен из исходника для сопоставления, основной режим — `argmax`.
6. **`dual_crl_ppo.py`, параметры**. Параметры LEO переименованы в CRL. По таблице 8 статьи заданы `representation_dim=64`, одна эпоха CRL и минибатч 2048. `--crl_offset_cap` по умолчанию 64 для семантических целей и 32 для наборов признаков наблюдения, согласно таблице 8. `--crl_termination_discount` по умолчанию выключен, поскольку для основных Dual-CRL-PPO экспериментов по таблице 8 и экспериментов масштабирования используется поглощающий класс без дополнительного штрафа. Для абляции с формулой (8) укажите, например, `--crl_termination_discount 0.8`.
7. **`envs/gridworld/gridworld_state.py`**. Массив по умолчанию переведён на `default_factory` с тем же фиксированным seed. Это требуется Python 3.12 для `flax.struct.dataclass`; содержание карты не менялось.

8. **`envs/craftax/observation_goals.py` и `envs/envs.py`**. Для масштабирования из приложения B.1 добавлена отдельная реализация целей по индексам признаков. Full Craftax использует каждый из 9 637 признаков одноразрядного символического наблюдения. Classic начинает с 1 562 признаков и исключает никогда не встречающиеся `INVALID` и `WOOD` на всей карте, невозможные значения под игроком в центре карты, четыре типа мобов в клетке игрока и нулевое здоровье у живого игрока. Остаётся 1 419 целей. Индексы и порядок признаков закреплены исходным `CRAFTAX_*_OBS_KEY_ORDER`. В rollout достижение всех целей вычисляется выборкой признаков, а одноразрядная маска создаётся только для командованной цели. Это предотвращает квадратичный массив размером 9 637 × 9 637. Оба набора проходят через прежние среды Craftax и сохраняют семантические наборы отдельным режимом.
9. **`dual_crl_ppo.py`, выбор набора**. Добавлен `--goal_set observation`, отдельный шаг подсчёта целей и построение примерной маски для инициализации PPO. По таблице 8 ограничение будущего окна автоматически становится `k_max=32` для целей по признакам наблюдения; явный `--crl_offset_cap` может его переопределить.

## Запуск

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python dual_crl_ppo.py --env_name Craftax-Classic-Symbolic-v1 --no_use_wandb
```

Скрипт запускайте из корня репозитория. Для Full Craftax оставьте `Craftax-Symbolic-v1` по умолчанию. Для Gridworld задайте `--env_name Gridworld-v1 --network_type symbolic_flat`. GPU ускоряет обучение, а полный эксперимент статьи требует порядка `10^9` шагов среды. По умолчанию используются исходные семантические наборы из 136 и 512 целей. Отдельные наборы по признакам наблюдения выбираются флагом `--goal_set observation`. Craftax Classic содержит 1 419 целей, Full Craftax — 9 637:

```bash
.venv/bin/python dual_crl_ppo.py --env_name Craftax-Classic-Symbolic-v1 --goal_set observation --no_use_wandb
.venv/bin/python dual_crl_ppo.py --env_name Craftax-Symbolic-v1 --goal_set observation --no_use_wandb
```


Для тысяч целей логируются агрегированные показатели вместо отдельного показателя для каждого признака. Среднее число завершённых целей защищено от деления на ноль в обновлениях без терминального перехода.

Терминальные наблюдения исходных обёрток недоступны после автоматического сброса. Поэтому переход с `done=True` даёт цель `∅` и успешная цель, одновременно достигнутая на последнем шаге, не учитывается. `--crl_termination_discount` применяет штраф ко всем `done`, включая лимит времени, так как обёртки не передают отдельный признак причины завершения.
